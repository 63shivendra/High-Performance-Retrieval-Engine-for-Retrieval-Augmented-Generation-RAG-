A search engine, built from scratch.

Inverted indexes with positional postings, a Boolean query parser, TF and TF-IDF ranking, and two query-processing strategies (term-at-a-time and document-at-a-time). Written in pure Python with no search library, and benchmarked against Elasticsearch on 100K documents.

    How it works

    1. Preprocesslowercase · strip URLs/HTML · tokenize · drop stopwords · Porter stem
    2. Indexterm → [(doc, tf, positions)] postings; IDF = log(N / df)
    3. Store / compressJSON or SQLite · Elias γ/δ, VByte or Zlib with gap encoding · skip pointers
    4. ParseAND / OR / NOT / PHRASE / ( ) via shunting-yard → RPN
    5. ProcessTAAT score accumulators or DAAT multi-pointer merge
    6. RankΣ tf (TF) or Σ tf · idf (TF-IDF), top-k

    Findings

    • TAAT beat DAAT by ~70% in Python: sequential postings scans have better cache locality and lower interpreter overhead. DAAT tends to win in compiled engines.
    • Boolean retrieval paradox: highest throughput (344 QPS) but the worst tail latency, because large unranked result sets are expensive to materialise.
    • Compression is a dial: Zlib is the balanced choice; Elias coding saves the most space but adds ~12× latency from bit-level decoding in Python.
    • Skip pointers (√n spacing) give ~3% on in-memory AND queries, with larger gains expected for disk-resident postings.

    About this demo

    The live index is built at server start from a ~4,000-article English Wikipedia sample, using the same src/ indexers as the benchmark. Latencies shown are measured around the engine's query call only.
